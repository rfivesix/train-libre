## 2025-02-20 - Prevent SQL Injection during Table Restore
**Vulnerability:** In `lib/core/infrastructure/icloud_sync_service.dart`, the `_copySnapshotIntoLiveDatabase` function read table names from `sqlite_master` and injected them directly into a raw `DELETE FROM` SQL query without validation. Although these came from the snapshot, an attacker modifying the snapshot database to include malicious table names could have triggered a SQL injection.
**Learning:** Table names and other identifiers cannot be parameterized in SQLite (using `?`). They must be validated before interpolation into SQL strings, even if they originate from what seems like an internal or "safe" system table like `sqlite_master`, especially during import/restore boundaries where the file might have been tampered with externally.
**Prevention:** Always validate dynamically resolved table names using a strict allowlist or a regex like `RegExp(r'^[a-zA-Z0-9_]+$')` before using them in raw string interpolation for SQL queries.
