## 2024-06-25 - Avoid Chained Iterable Pipelines in Core Rules Engines
**Learning:** In heavily accessed pure domain functions (like `DoubleProgressionEngine` which evaluates complex progression rules for every workout set), chained iterable pipelines such as `.map().whereType().toList()` followed by `.reduce()` create significant temporary object allocations. These intermediate lists and lazy wrapper closures (MappedIterable, WhereIterable) cause frequent GC sweeps and slow down core progression loops, especially when multiple historical sessions are evaluated at once.
**Action:** Replace these pipelines with explicit, single-pass `for` loops that directly compute the necessary aggregate (e.g., tracking a maximum value or date) while filtering out nulls inline. This eliminates the creation of intermediate collections and the overhead of closure evaluations.
